# コードブロックの外部ツール

右サイドバーのヘッダーにある検証アイコンで、編集中の文書内にあるMarkdown本文と対応済みコードブロックを整形・検査します。独自ディレクティブのDSLと未設定のコード本文は保持します。設定の `Auto validate` を有効にすると変更後に同じ処理を自動実行します。未設定の言語はそのまま保持します。整形結果はUndo可能で、診断は本文の下線にマウスを重ねると確認できます。実行中に本文・編集対象が変わった場合、結果を破棄します。

`Shift+Alt+F` も検証アイコンと同じく、カーソル位置に関係なく現在のページ全体を整形・検査します。保存アイコンは常時表示し、保存済みは緑、エラーは赤、手動保存で未保存の変更がある場合はオレンジになります。

設定はドキュメントルート（manifest.yamlと同じ階層）の `.dooc/editor-tools/<コードフェンスの言語名>.json` に置きます。`js` と `javascript` は別の設定名です。設定変更は次の実行から有効になります。

例: `.dooc/editor-tools/typescript.json`

```json
{
    "formatter": ["pnpm", "exec", "prettier", "--stdin-filepath", "example.ts"],
    "linter": ["node", ".dooc/editor-tools/check-typescript.mjs"]
}
```

必要なツールはドキュメント側の環境へインストールしてください。`formatter` / `linter` は片方だけでも構いません。実行ファイルと引数の配列で指定し、シェル展開は行いません。作業ディレクトリはドキュメントルートです。設定されたコマンドはローカルユーザーの権限で動くため、信頼する設定・スクリプトだけを使用してください。

両方とも標準入力でコード本文（末尾改行付き）を受け取ります。一時ファイルは作りません。ファイル名が必要なツールには上の `--stdin-filepath` のような引数を指定します。ツールの実行時間は10秒、出力は1MiBまでです。

- formatter: 整形後のコードを標準出力へ返し、終了コード0で終了。空出力で既存コードが消える場合や閉じフェンスが混入する場合は反映しません。
- linter: 次のJSON配列を標準出力へ返すアダプターを用意します。終了コード0・1を受理します。診断がなければ `[]` を返します。その他のログは標準エラー出力へ送ります。

```json
[
    {
        "message": "不要な変数です",
        "severity": "warning",
        "line": 1,
        "column": 7,
        "endLine": 1,
        "endColumn": 8
    }
]
```

位置はコード本文内の1始まり、列はUTF-16単位です。終点は範囲に含みません。`endLine` / `endColumn` は対で省略可能。`severity` は `error` / `warning` / `info` で、省略時は `warning` です。ESLint等の独自JSON出力はこの形式へ変換してください。

設定・アダプターはソースZIPにも含まれます。実行APIと検証アイコンは編集モード限定で、localhost / 127.0.0.1 / [::1] から利用します。preview・配布HTMLにツール実行機能は含めません。表示の色付けは従来どおりShikiが担当します。

閉じたコードフェンスが対象です。リスト・引用内のブロックにも適用します。LSP接続とbuild時のlintは未対応です。

検証アイコンは、正常なら緑、エラーがあれば赤、手動で未適用の変更があればオレンジになります。

`Auto validate` と `Auto save` は初期状態でONです。明示的にOFFにした設定は保持します。
